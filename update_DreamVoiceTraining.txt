## 3. AUR aktualisieren
# makepkg kennt nur pacman, nicht das AUR. Zwei Abhängigkeiten liegen im AUR
# (python-sounddevice, python-praat-parselmouth), deshalb paru statt makepkg.
cd ~/aur/dream-voicetraining
sudo rm -rf pkg src; rm -f *.pkg.tar.zst *.tar.gz    # Reste vom letzten Lauf
nano PKGBUILD                        # pkgver=1.0.3, pkgrel=1 (wie im Projekt)
updpkgsums                           # lädt neuen Tag, ersetzt Checksumme
paru -Ui                             # bauen + installieren, löst AUR-Deps
                                     # yay:  yay -Bi .
cd ~ && dream-voicetraining          # testen: startet? Icon? Prozessname in btop?
cd ~/aur/dream-voicetraining
makepkg --printsrcinfo > .SRCINFO    # PFLICHT
git add PKGBUILD .SRCINFO            # NIE git add -A
git commit -m "Update to v1.0.3"
git push origin master               # AUR nutzt master!

Danach PKGBUILD ins Projekt zurückspiegeln, sonst laufen beide auseinander:
cp ~/aur/dream-voicetraining/PKGBUILD \
   ~/Schreibtisch/voice-training/Dream-VoiceTraining/packaging/PKGBUILD


## Nützliche Abkürzung (~/.config/fish/config.fish)
function pkgclean
    sudo rm -rf pkg src
    rm -f *.pkg.tar.zst *.tar.gz
end


## Fehler beim AUR-Bau

updpkgsums gibt 404
  -> GitHub-Tag existiert noch nicht. Erst Schritt 2 fertig machen.

"Ziel nicht gefunden: python-sounddevice"
  -> liegt im AUR, makepkg kann es nicht holen. paru -Ui benutzen.
     In extra:  python, python-numpy, python-pyqtgraph, python-colorama,
                pyside6, portaudio
     Im AUR:    python-sounddevice, python-praat-parselmouth (dein Paket)
     Neue Namen immer mit pacman -Si bzw. paru -Si prüfen, nie raten.

paru panickt: "Result::unwrap() on an Err value: .../pkg"
"Keine Berechtigung (os error 13)"
  -> Reste eines abgebrochenen Laufs gehören root. pkgclean, dann erneut.

"ist aktuell -- überspringe Erstellen"
  -> fertiges .pkg.tar.zst mit gleicher pkgver-pkgrel liegt noch da, makepkg
     baut nicht neu und installiert den alten Stand. pkgclean.
     Tritt auf, wenn man einen Tag verschiebt statt die Version anzuheben.

"cd: .../src/dream-voicetraining-1.0.0: nicht gefunden"
  -> Das GitHub-Archiv entpackt nach Dream-VoiceTraining-1.0.0 (Repo-
     Schreibweise), nicht nach dem Paketnamen. Im PKGBUILD steht dafür
     _repo=Dream-VoiceTraining. Beim Umbenennen des Repos mit anpassen.

.SRCINFO vergessen
  -> AUR lehnt den Push ab. Nach JEDER PKGBUILD-Änderung neu erzeugen.

Falscher Ordner
  -> AUR-Push NUR aus ~/aur/dream-voicetraining. Projekt-PKGBUILD ist Kopie.

pkgver mit Bindestrich
  -> 1.0.3 ist sauber; ein Alpha hieße 1.0.3_alpha (Unterstrich), nie -alpha.

Branch verwechselt
  -> Projekt = push origin main, AUR = push origin master.

Bau von python-praat-parselmouth schlägt fehl
  "No module named skbuild"
    -> makedepends unvollständig. Nötig: cmake, ninja, pybind11,
       python-scikit-build, python-build, python-installer,
       python-setuptools, python-wheel.
  "Missing dependencies: cmake>=3.18"
    -> pyproject.toml will cmake als PYTHON-Paket. Arch liefert es als
       Systemprogramm, das der Prüfer nicht sieht. Deshalb steht im PKGBUILD
       python -m build ... --skip-dependency-check
  Läuft nach einem Python-Sprung gar nicht mehr
    -> PKGBUILD.python-praat-parselmouth-bin nehmen, installiert das fertige
       Wheel ohne Compiler.


## Fehler beim Programm

Paket baut durch, stürzt beim Start ab
"argument 1 has unexpected type 'PenStyle'" + SIGSEGV
  -> pyqtgraph hat PyQt6 statt PySide6 gewählt. In der venv fällt das nie auf,
     weil dort nur PySide6 liegt. main.py und dialogs.py setzen deshalb vor
     dem Import: os.environ.setdefault("PYQTGRAPH_QT_LIB", "PySide6").
     IMMER das installierte Paket testen, nie nur python main.py im Projekt.

check() bricht ab: "No module named colorama"
  -> pyqtgraph importiert colorama beim Laden, führt es selbst aber nur als
     Check-Abhängigkeit. Deshalb steht python-colorama in depends.

venv startet nicht mehr nach dem Verschieben des Ordners
  -> activate.fish trägt absolute Pfade ein. rm -rf .venv,
     python -m venv .venv, pip install -r requirements-dev.txt


## Fehler beim AppImage

"Squashfs image uses (null) compression"
  -> alte AppImageKit-Laufzeit versteht nur xz und zlib, appimagetool packt
     zstd. Das Skript benutzt deshalb die Hybrid-Laufzeit; --classic setzt
     für die FUSE-2-Variante --comp xz.

AppImage startet, findet aber kein Mikrofon
  -> PortAudio kommt vom Wirtssystem und ist bewusst nicht gebündelt.
     Auf dem Testsystem portaudio bzw. libportaudio2 installieren.
